# Changelog review checklist

- [ ] Repository changelog categories, parser expectations, and release process are preserved.
- [ ] Exact source, diff, and shipping scope were inspected.
- [ ] Entry opens with the merchant's observable outcome.
- [ ] Applicable defaults, optional modes, per-action overrides, requirements, and practical limits are stated accurately.
- [ ] When generated coupons are in scope, available modes and their verified defaults are described accurately.
- [ ] Feature ownership and add-on dependencies are attributed to the correct product.
- [ ] Unreleased fixes are not described as customer-experienced bugs.
- [ ] Deferred or unverified behavior and unsupported compatibility/performance claims are omitted.
- [ ] Security advisories retain the repository's required wording and category.
- [ ] Internal engineering notes are separate; customer-required upgrade/migration actions and visible effects remain in customer notes.
- [ ] No version, date, historical entry, or unrelated changelog text was invented or altered.
- [ ] New UI labels remain provisional until the product owner tests and finalizes them.
